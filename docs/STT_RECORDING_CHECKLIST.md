# STT benchmark recording checklist (Task 7.2)

Generated by `python -m app.stt_bench checklist` from `bench/customer_voice.json` and `bench/voice_controls.json`; do not edit by hand. The words below are the **planned scripts**: they are what each volunteer is asked to say, not what was said. Nothing here is verified gold.

## Before recording (owner)

1. Volunteers: six people (S1..S6; mixed gender / age, Karachi accents) who agreed in writing (a message is enough) to a short fictional recording, private storage until the benchmark closes, use only for this evaluation, and deletion afterwards. Nobody says a name, number or address of their own. Free Gemini tiers may train on data: team / volunteer phones only.
2. Phones: three devices, one per class (`android_low`, `android_mid`, `iphone`). Speakers share the devices as in the session plan. Add each device's number to the Meta test-number recipient list (owner only).
3. Keep the private sheet (never in Git or chat): speaker S-number -> person, device class -> phone number, and for every send: item id, send time with UTC offset, device, retake yes / no (which send counts).
4. Check that `STT_PROVIDER` is `off` in the runtime while recording (owner; this task changes no setting), otherwise each note spends Scribe minutes before the benchmark. Audio is stored by Task 5.3 either way (`S3_BUCKET` set, migration 012). With STT off each note gets the usual "please type" reply; ignore it.

## How to record each note

- Inside WhatsApp, to the test number: press and hold the microphone (hold-to-record voice note, **not** an audio file, not a forward), speak, release to send. No editing, no trimming, no speaker-phone playback of a recording (controls excepted: the music clip).
- Leave about one second of natural pause before speaking and after finishing: R16 wants 3-45 s notes and the validator flags anything under 3.0 s (several scripts are only a few words long).
- Say the words naturally and in your own pace. If you stumble or change words, resend; note on the sheet which send counts. Only the counted send goes in the manifest (a duplicate id is rejected). If you still deviate from the script, that is fine: it is corrected at verification, not here.
- Send in item order within a session. One device session = one phone, one noise setting at a time (see the session plan).

## From a sent note to scored evidence

| Step | Who | What | Result |
|---|---|---|---|
| 1 Webhook capture | automatic | the note reaches the webhook, `inbound_audio` row, `fetch_audio` stores the bytes unchanged in the private bucket (`tenant/<agency>/audio/<id>.ogg`) | a stored object per note |
| 2 Manifest export | owner, in the worker container (read-only, `manzil_app` `DATABASE_URL`) | `python -m app.bench_manifest --agency-id <uuid> --since <start with offset> --until <end>` prints seq, conversation, received_at, status, is_voice, mime_type, duration_ms, byte_size, sha256, storage_key | CSV in arrival order |
| 3 Label | owner | match each row to the sheet by conversation (one phone) and received_at; add `item_id`, `speaker`, `phone`, `noise`; drop non-benchmark rows and uncounted retakes; every kept row must be `stored` | `bench/voice_manifest.csv` (committable: no phone, URL or text) |
| 4 Private audio | owner | download each kept `storage_key` object from the private bucket to a private local folder as `<item_id>.ogg`; never into Git | audio folder |
| 5 Validate | anyone | `python -m app.stt_bench validate --manifest bench/voice_manifest.csv --audio-dir <folder>`: ids, hashes, sizes, Ogg durations, pseudonymous labels, actual coverage (6 speakers, 3 phones, 15 / 10 / 5 noise, 30 + 5, 3-45 s) | errors / blockers list |
| 6 Human verification | a person who **listens** (preferably not the speaker), one item at a time | compare the audio with the planned script; if identical write `as_scripted: true`, otherwise `as_scripted: false` with the words actually said (`gold_transcript`) and the matching `gold_extraction`; controls: confirm what is audible (silence, music, Punjabi, long) | an entry in `bench/voice_gold_verified.json` bound to that recording's sha256 |
| 7 Review | second person | spot-check entries marked `as_scripted` and every deviation | `validate` shows `gold_verified` = 35 |
| 8 Score | owner approves provider spend first | `plan`, then `run --confirm-live` (docs/STT_BENCHMARK.md) | report: official 30-item criterion A, 27-item diagnostic, controls screen, control gate unverified |

Verified entry shape (one per item; do not create it from the script without listening):

```json
{"schema": 1, "items": {"CV-06": {"audio_sha256": "<sha256 of CV-06.ogg>", "verified_by": "<initials>", "verified_on": "<date>", "as_scripted": true}}}
```

## Retention

Audio stays in the private bucket until benchmark run #2 (Task 10.3 / 14.x), then the owner deletes the benchmark objects named in the manifest. No audio, phone number or private URL goes to Git, the report or chat.
